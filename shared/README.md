The Next.js and Netlify `/api/statement` endpoints require `Authorization: Bearer <STATEMENT_API_TOKEN>`. Set `STATEMENT_API_TOKEN` in the server deployment environment; an unset token disables execution. Keep this token out of public frontend environment variables and bundles. Existing browser playground callers need an authenticated server-side proxy that supplies the token.

Use a database account with SELECT privileges only on the intended playground databases. Query validation is an additional restriction, not a replacement for database permissions. The endpoint accepts one MySQL SELECT, rejects system databases and cross-database references, and allows only the functions listed in `statement-security.ts`. Unsupported SQL fails closed. Literal values in the SQL editor are intentionally part of the submitted program; schema lookup values remain bound parameters.

Set `STATEMENT_ALLOWED_DATABASES=game,demo` for Next.js and `TIDBCLOUD_STATEMENT_ALLOWED_DATABASES=game,demo` for Netlify (replace these examples with your actual playground database names). This comma-separated allowlist is mandatory when the connection URL has no database path, such as `mysql://name:<PASSWORD>@gateway01.us-east-1.prod.aws.tidbcloud.com/`. Next.js reads `DATABASE_URL`; Netlify reads `TIDBCLOUD_DATABASE_URL`. Neither URL needs a database suffix when the allowlist is set. If no allowlist is supplied, only the database explicitly present in the URL is permitted; a URL without a database fails closed with HTTP 503. Database names are case-sensitive and restricted to 1–64 ASCII letters, digits, or underscores; system databases cannot be allowlisted. Configure these values server-side only. No live database permissions are changed by this code.

For local Next.js development, copy `packages/playground-nextjs/.env.example` to `.env.local` in the same directory and configure `DATABASE_URL`, `STATEMENT_ALLOWED_DATABASES`, and `STATEMENT_API_TOKEN`; restart the dev server. Netlify-prefixed environment variables are not used by Next.js. `/api/schema` returns HTTP 503 for missing or invalid configuration and HTTP 502 for database access failures. It reads metadata only for allowlisted databases and does not execute `SHOW DATABASES`. Setting the server token alone does not authenticate browser requests.
