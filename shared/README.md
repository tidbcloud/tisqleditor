All Next.js and Netlify `/api/*` endpoints require `Authorization: Bearer <token>`, including schema, mock jobs/chat/refinement, and Netlify hello. Configure `API_TOKEN` for Next.js and `TIDBCLOUD_API_TOKEN` for Netlify. If the new variable is absent, the legacy `STATEMENT_API_TOKEN` is accepted for compatibility; an explicitly empty new variable disables access. Missing or invalid credentials return HTTP 401 before handler work. Keep tokens server-side and use HTTPS in deployed environments. Browser playground calls currently do not supply credentials: setting the server token alone does not enable the UI. An authenticated integration must supply the Authorization header; never embed the server token in public frontend environment variables or bundles.

Both deployments enforce the shared guard in central `/api/*` middleware and again in every handler. Schema, jobs, and hello accept GET only; chat2data and refinement accept POST only. Authenticated requests using other methods return 405 with an Allow header. Next.js also enforces exported method dispatch. Responses crossing middleware have `Cache-Control: no-store` so authenticated data is not publicly cached. The AI and job endpoints remain local mocks and do not use Chat2Query credentials.

The Run action and `/api/statement` endpoint have been removed from both playgrounds. There is no API for executing user-supplied SQL. Use a database account with read-only access to intended playground schema metadata; schema lookup values remain bound parameters.

Set `STATEMENT_ALLOWED_DATABASES=game,demo` for Next.js and `TIDBCLOUD_STATEMENT_ALLOWED_DATABASES=game,demo` for Netlify (replace these examples with your actual playground database names). This comma-separated allowlist is mandatory when the connection URL has no database path, such as `mysql://name:<PASSWORD>@gateway01.us-east-1.prod.aws.tidbcloud.com/`. Next.js reads `DATABASE_URL`; Netlify reads `TIDBCLOUD_DATABASE_URL`. Neither URL needs a database suffix when the allowlist is set. If no allowlist is supplied, only the database explicitly present in the URL is permitted; a URL without a database fails closed with HTTP 503. Database names are case-sensitive and restricted to 1–64 ASCII letters, digits, or underscores; system databases cannot be allowlisted. Configure these values server-side only. No live database permissions are changed by this code.

For local Next.js development, copy `packages/playground-nextjs/.env.example` to `.env.local` in the same directory and configure `DATABASE_URL`, `STATEMENT_ALLOWED_DATABASES`, and `API_TOKEN`; restart the dev server. Netlify-prefixed environment variables are not used by Next.js. `/api/schema` returns HTTP 503 for missing or invalid configuration and HTTP 502 for database access failures. It reads metadata only for allowlisted databases and does not execute `SHOW DATABASES`. Setting the server token alone does not authenticate browser requests.
